## Question 1: LFO Chaos: Lorenz Attractor Curve

### Finding

From `serum_2_0_21_schema_snapshot.json`:
```
lfo.kParamType.enum_values = ['Rossler', 'Lorenz', 'RandomSH', 'Path']
```

### Answer

**The Lorenz attractor curve rendering is a DERIVED VISUALIZATION.**

- **Stored preset state:** `lfo1.shape` (or `lfo.kParamType` in schema terms) = enum value `"Lorenz"` (one of four choices).
- **Visual rendering:** The animating butterfly/double-loop curve shown on screen is a deterministic real-time visualization of the Lorenz chaos algorithm, updated with each buffer, based on that enum choice.
- **No independent storage:** The curve itself — its shape, orientation, animation speed — is NOT a separate stored field. It is deterministically derived from the enum value alone.

### Observation modality

- **Type:** `SELECTOR` (enum/text capture)
- **Implementation:** OCR/transcription of "Chaos: Lorenz" text label, validated against `['Rossler', 'Lorenz', 'RandomSH', 'Path']` vocabulary
- **No additional modality needed:** The curve is runtime-computed from the enum, not an observable preset parameter in its own right

### Classification

```
observation_kind = "SELECTOR"
required_modality = TEXT
shape_observable = false
```

## Question 2: Oscillator Waveform Shape

### Finding

From `serum_2_0_21_schema_snapshot.json`:
```
wavetable_oscillator.kParamTablePos = {
  'key': 'kParamTablePos', 'kind': 'float',
  'default': 0.0, 'min': 0.0, 'max': 256.0,
  'unit': 'table frame', ...
}

simple_wavetables = {
  'default': ..., 'analog_basic': ..., 'analog_warm': ...,
  'pwm': ..., 'analog_mini': ..., ... (12 total)
}
```

Also from schema: `OscillatorSpec.wavetable` is a string enum pointing to one of the keys in `simple_wavetables`.

### Answer

**The oscillator waveform shape is DETERMINISTICALLY DERIVED, not stored independently.**

- **Stored preset state:** Two numeric/enum fields per oscillator:
  1. `osc[A/B/C].wavetable` — enum name of the loaded wavetable (e.g., `"analog_warm"`)
  2. `osc[A/B/C].wt_position` — numeric frame offset within that wavetable (0.0 to 256.0, depending on table frame count)
- **Visual rendering:** The waveform shape displayed on screen is generated by: `render(wavetable[name], position)`. Different wavetable choices produce different shapes, but the shape itself is NOT separately stored.
- **No independent shape field:** There is no `osc.waveform_shape` or `osc.visual_shape` parameter. The shape is a runtime computation.

### Observation modality

- **Type:** `SELECTOR` (text) + `CONTROL` (numeric)
- **Implementation:**
  1. Capture `wavetable` text (enum): OCR "Default Shapes" / "Analog Basic" / etc., validate against known wavetable names
  2. Capture `wt_position` numeric: OCR readout or pixel calibration (0–256)
  3. Derive expected shape: `get_wavetable_waveform(wavetable_name, position)` from the atlas
  4. Verify UI shape matches expected shape if needed (defensive check, not required for reproduction)
- **No independent GRAPH observation needed:** The curve/shape is reconstructible from the two stored fields alone

### Classification

```
observation_kind = "SELECTOR" (wavetable) + "CONTROL" (position)
required_modality = TEXT + NUMERIC
shape_observable = true  (derived, reconstructible)
shape_stored = false
```
